## Data
**Section 10 uses restricted data and this archive does not contain them.** No individual record, and no file derived from individual records, is here or in the Git history; the aggregate outputs of the real run are withheld as well, pending confirmation of the disclosure conditions with the survey and the data provider. What is public is the whole pipeline, a synthetic input with the same structure (regenerated byte-identically by `kit/R/15_make_synthetic.R` under a UTF-8 locale), the expected outputs of running the pipeline on it, and a script that reprints every number quoted in Section 10 from the aggregate outputs. Sections 1 to 9 and the simulation appendix use no data at all. See `kit/KIT_README.md` for the access route and the number-to-output map.

## Environment

- R (≥ 4.3). The simulations and deterministic checks need base R and, for
  `sims/check_multiwave_completion.R`, the package `lpSolve`. The JLPS pipeline in `kit/` additionally
  needs `haven`, `data.table` and `panelcond` (`remotes::install_github("sokubo/panelcond@v0.1.4")`).
- Python 3 (standard library only) for `sims/check_design_rank.py`; Python 3 with `matplotlib` for the one
  figure (`manuscript/figures/make_fig1_funnel.py`).
- Quarto 1.6.42 (Pandoc 3.4) + XeLaTeX (TeX Live 2023) for the manuscript; `manuscript/build_latex.py` reproduces
  `main.pdf` and `latex/main.tex`. The PDF engine (XeLaTeX) and the citation style (`manuscript/latex/chicago-author-date.csl`,
  Pandoc's built-in Chicago author-date style) are pinned in `main.qmd`. The numerical scripts do not depend on
  this toolchain; exact pagination and citation formatting do, so a build with another Quarto or TeX Live version
  can differ in page breaks and reference layout without any change to a statement, number or formula.
- **Set a UTF-8 locale before running anything in `kit/`** (`export LC_ALL=C.UTF-8` on Linux). The item
  labels are Japanese, and in a non-UTF-8 locale `haven` writes them as `<U+XXXX>` escapes, which changes
  the bytes of the synthetic input without changing any value. Under a fixed UTF-8 locale the synthetic
  input regenerates byte-identically; its SHA-256 is
  `760b722ad0728a80773003ff3b0cda6debf6bf1b497d3a1a78600cc493f75289`.

Steps 1–8 are self-contained and use no data; steps 9–10 are run from `kit/` with the environment
variables set as in `kit/KIT_README.md` (Section 2). Step 7 fails if any quoted value no longer matches its
output cell, and its `--selftest` mode confirms that a perturbed value and a deleted row make it fail.
Steps 9–10 are the **pipeline check**: they exercise the code that produces the 2011-episode results of
Section 10, on synthetic input whose numbers are not the paper's; the 2019 battery scripts (`kit/R/11*`)
need a confidential item map and are not exercised. Step 11 is the prose-versus-output check for
Section 10, run by a licensed user against the real aggregates.

## The restricted data

Section 10 applies the designs of Section 7 to the Japanese Life Course Panel Surveys. **No individual
record, and no file derived from individual records, is in this archive or in its Git history**, and
the item-level aggregate outputs of the real run are not shipped either, pending confirmation of the
disclosure conditions with the survey and the data provider. The paper itself reports the aggregates it
uses (Section 10 and the appendix table of the negative-control battery). `kit/KIT_README.md` states
the access route, what a licensed user runs, and the map from every number in Section 10 to the output
file and column it comes from. The paper's claims in Sections 1–9 do not depend on the microdata: they
are theorems, and the appendix that supports them is synthetic throughout.

## Map from manuscript objects to code

- Theorem 1, Corollaries 1–3, Remarks 1–2, the central-binding and logistic examples, Theorem 3: `sims/check_funnel_examples.R`, `sims/sim1_bounds.R`.
- Corollary 4 (discrete outcomes), Lemma 2 and Theorem 2 (pattern completion), Corollary 6 (mean bounds): `sims/check_multiwave_completion.R`; the counterexamples to the earlier forms of Corollary 4 and Corollary 5, and Proposition 1: `sims/check_funnel_examples.R`.
- Theorem 4 and Corollary 7 (two refreshments, generational case): `sims/sim2_multicohort.R`; the common-loading example and the marginal-versus-joint information example of Theorem 4(a): `sims/check_funnel_examples.R` (blocks 11 and 12).
- Propositions 2–6 (the three designs, their biases, the diagnostics) and the variance formulas: `sims/sim3_designs.R`.
- Theorem 5, Proposition 7 and Table 1 (design rank, stride, follow-up): `sims/check_design_rank.py`.
- Section 10: `kit/` — see `kit/KIT_README.md`.
